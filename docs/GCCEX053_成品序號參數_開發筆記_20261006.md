# GCCEX053 合同BOM(成品/料件)明細表：新增成品序號參數 開發筆記

> 最後更新：2026-10-06  
> 環境：DEV（尚未在資料庫編譯或執行）  
> 模組：EBS Concurrent Program／PL/SQL Package  
> 分支：`claude/report-product-number-range-o7z2zi`

## 1. 需求與背景

- 報表 `GCCEX053:合同BOM(成品/料件)明細表` 要新增兩個參數：**成品序號(起)**、**成品序號(迄)**，參數畫面位置在「報表格式:成品或料件」之後。
- 原有參數：企業內部編碼、合同號起、合同號迄、成品料號ID、料件料號ID、報表格式:成品或料件。
- 程式：`APPS.GCCEX053_PKG.MAIN`（`.pks`／`.pkb`，Big5 編碼、CRLF 換行）。

## 2. 問題與測試紀錄

### 2026-10-06｜「成品序號」對應哪個欄位

- 依報表表頭判斷，「成品序號」對應：
  - 成品格式（`P_G_MARK = '4'`）：`FL_GCC_HZ_EXG_ITEM.EMS_G_NO`
  - 料件格式（`P_G_MARK = '3'`）：`FL_GCC_HZ_IMG_ITEM.FG_EMS_G_NO`（料件所屬成品的序號）
- 最終解法：兩個 cursor 各自依上述欄位加範圍條件。

### 2026-10-06｜欄位型態不同

- 現象：第一版假設兩個欄位都是 NUMBER，直接和 NUMBER 參數比較。
- 查核結果（使用者提供 `ALL_TAB_COLUMNS` 查詢截圖）：

  | 表 | 欄位 | 型態 |
  |---|---|---|
  | FL_GCC_HZ_EXG_ITEM | EMS_G_NO | NUMBER(19,0) |
  | FL_GCC_HZ_IMG_ITEM | EMS_G_NO | NUMBER(19,0) |
  | FL_GCC_HZ_IMG_ITEM | FG_EMS_G_NO | VARCHAR2(20) |

- 原因判斷：`FG_EMS_G_NO` 是 VARCHAR2。和 NUMBER 比較時，Oracle 會自動 `TO_NUMBER`，只要有一筆非數字值就會發生 ORA-01722。
- 未採用的方法：
  - 改用文字比較：順序會錯，例如 `'10' < '2'`。
  - `TO_NUMBER(... DEFAULT NULL ON CONVERSION ERROR)`：需要 12.2 以上，資料庫版本未確認。
- 最終解法：先用 `REGEXP_LIKE` 確認是純數字再轉換，非數字視為 NULL。
- 修改物件：`GCCEX053_PKG.pkb`。

### 2026-10-06｜成品序號起迄檢核

- 需求：成品序號(起)不可大於成品序號(迄)。
- 做法：`MAIN` 開頭檢核，起大於迄時設定 `ERRBUF`、`RETCODE := 2`，寫入 Log 和 Output 後 `RETURN`。
- 未採用的方法：在 Value Set 做跨參數檢核（需要表格型 Value Set 搭配 `$FLEX$`，設定較複雜，也較難維護）。
- 修改物件：`GCCEX053_PKG.pkb`。

## 4. 最終設定摘要

- 參數留空代表那一邊不限制。
- 兩個都有輸入且起大於迄時，Request 以 Error 結束，不產生報表資料。
- 新參數一定要排在 `P_G_MARK` 之後，Concurrent Program 參數的 Sequence 也要排在最後。

- [ ] Concurrent Program 新增兩個參數（Value Set 名稱待確認，建議數字型，例如 `FND_NUMBER`）。
- [ ] 待確認：`FG_EMS_G_NO` 是否有前置零或非數字資料，可用下方 SQL 查核。

- 風險：如果有輸入序號範圍，`FG_EMS_G_NO` 為非數字的料件不會出現在報表中。

```sql
-- 查 FG_EMS_G_NO 非純數字的資料（唯讀查核）
SELECT FG_EMS_G_NO, COUNT(*)
  FROM FL_GCC_HZ_IMG_ITEM
 WHERE NOT REGEXP_LIKE(TRIM(FG_EMS_G_NO), '^[0-9]+$')
    OR FG_EMS_G_NO IS NULL
 GROUP BY FG_EMS_G_NO;
```
